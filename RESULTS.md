# results

the canonical numbers live in `bench/SUMMARY.md` and the JSON files next to the harnesses. this file explains what was measured and what the numbers do not cover.

## method

- text: 20 documentation pages. baseline is the page reduced to visible text with scripts and styles removed. quarry is the full extracted text. tokens use the o200k tokenizer on the returned text.
- selection: 10 pages, one question each, top three sections returned. tokens use o200k. recall means the required string appears in the returned sections.
- hosted reader: 6 pages against `r.jina.ai`. tokens use o200k.
- browser fixtures: 19 local flows. quarry tokens are exact. the screenshot row is the 1,366-token frame formula, not a measured screenshot.
- browser real flows: 10 flows across mdn, react docs, github, and wikipedia. quarry tokens are exact. the chrome devtools baselines were recorded as `chars / 4` and are approximate. the DOM assertion checks the page after the clicks, not the returned state payload.
- klawva: one hiring flow up to checkout, 5 runs per arm. both sides exact o200k. no payment was made.

## current results

read `bench/SUMMARY.md`. it is regenerated by `npm run bench` and is the only table kept current.

## what the numbers do not cover

- actions are scripted, not chosen by a model.
- model latency is not measured.
- the real-flow baselines mix `chars / 4` with exact counts.
- browser screenshot tokens are a formula.
- runs are single unless stated, on one machine and one network.
- selection recall is a substring check on questions written with knowledge of the pages.
